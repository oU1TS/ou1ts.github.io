# Walkthrough - Initiatives Performance Metrics Database Integration

## 1. Overview
The **Initiatives Performance Metrics** section (`#initiativesDashboardCard`) in `ou1ts.github.io` now connects directly to the live child project tables in the central Supabase database (`portal_resources` and `stars` for the live `portal` / "Projects Hub" project). 

Furthermore, the dashboard dynamically filters cards according to the active user's `project_tags` array in `public.profiles`: **only initiatives enrolled under the user's profile are displayed**. When an initiative's database tables are still in development, realistic readiness telemetry is displayed. For visitors who are logged out or have no child tags, clean empty-state interfaces guide them to join.

### 2.2 Dynamic Project Tags Filtering & Real Child Tables Query ([`index.js`](../../index.js))
1. **Project Roster Tag Mapping**:
   Tagged each primary project with its child ecosystem tag (`tag: "portal"`, `tag: "archive"`, `tag: "scheduler"`, etc.).
2. **`getVisibleInitiatives()`**:
   Inspects `currentSessionUser.project_tags` and filters `primaryProjects` strictly to those whose tag is present.
3. **`fetchProjectMetricsFromDB()`**:
   - Queries `public.portal_resources` and `public.stars` directly for live resource and star counts.
   - Populates "Projects Hub" (`portal`) with real data (58 live resources, active stars, online status).
   - Generates realistic roadmap readiness for any other child project tags present on the profile.
4. **`renderProjectMetricsDashboard()` & `updateMetricsGalleryView()`**:
   - Only displays cards for initiatives the active user has in `project_tags`.
   - Displays a clean empty state with direct CTA if no child initiatives are enrolled or if the user is not logged in.
   - Mobile carousel and directory modal adapt to the visible initiatives count.
5. **Auth Synchronization**:
   `syncAuthStatus()` and `signOutUser()` instantly re-render the dashboard and aggregate pills when logging in or out.
