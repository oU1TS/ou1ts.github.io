# Implementation Plan - Custom Responsive Dropdowns with Text Wrapping

Replace native select dropdowns with an accessible, high-contrast, fully responsive custom dropdown component that stays strictly within the mobile screen bounds and wraps option text across multiple lines.

## User Review Required

> [!IMPORTANT]
> **Zero Disruption to Existing Form Logic**:
> The underlying `<select>` inputs will be preserved as accessible hidden controls. When an option is selected in the custom dropdown, it synchronizes the value directly with the `<select>` element and dispatches a standard `change` event, preserving full compatibility with form submission, validation, and auto-population.

## Proposed Changes

### 1. Custom Dropdown Architecture & Styling (`index.css`)
- **Container Constrained to Viewport**:
  - `.custom-select-wrapper` will have `position: relative; width: 100%; max-width: 100%; box-sizing: border-box;`.
- **Trigger Element**:
  - Replaces the visual `<select>` field with identical glassmorphic styling, padding for the left icon, and a rotating chevron arrow on the right.
- **Dropdown Menu Container**:
  - `position: absolute; left: 0; right: 0; width: 100%; max-width: 100%;`
  - Clamped with `max-height: 240px; overflow-y: auto;` with smooth custom scrollbars.
  - `box-sizing: border-box; z-index: 100;` ensuring it never extends horizontally beyond the card or mobile screen.
- **Multi-Line Option Items**:
  - `.custom-select-option` will have `white-space: normal; word-wrap: break-word; line-height: 1.35;`
  - Options will wrap into 2 lines naturally if they exceed the container width on narrow screens (e.g. 320px–380px mobile devices).
  - High contrast colors in dark mode (`#161b26` background, `#f8fafc` text) and light mode (`#ffffff` background, `#0f172a` text).

---

### 2. Custom Dropdown Script Engine (`index.js`)
- **Component Builder `initCustomDropdowns()`**:
  - Discovers all `<select>` inputs inside `.input-wrapper` (`#registerDept`, `#editDept`, `#editBlood`).
  - Hides the native `<select>` (visually hidden, accessible) and builds the custom trigger and option menu DOM.
  - Keeps option labels synchronized when values change programmatically (e.g. when `populateProfileUI()` runs).
- **Interactivity & Event Handling**:
  - Click trigger: toggles menu open/close, rotates chevron.
  - Click option: updates the custom trigger text, updates `<select>.value`, dispatches `new Event('change')`, and closes menu.
  - Click outside or Escape key: closes any active dropdown menus.
  - Accessibility: `role="listbox"`, `role="option"`, `aria-expanded` state attributes.

---

### 3. Markup Alignment (`index.html`)
- Ensure `<select>` containers inside `#registerForm` and `#profileEditForm` are structured cleanly for seamless custom dropdown attachment.

---

## Verification Plan

### Automated & Manual Verification
1. **Mobile Viewport Test (< 375px)**:
   - Test on simulated mobile viewports (320px, 360px, 375px, 412px).
   - Open `#registerDept` and `#editDept`.
   - Verify the dropdown menu does NOT produce horizontal scroll or clip off-screen.
   - Verify long options like *"Computer Science & Engineering (CSE)"* and *"Electrical & Electronic Engineering (EEE)"* wrap into 2 lines.
2. **Form Interaction & Data Persistence**:
   - Select a department in the registration form; verify form submit receives the selected value.
   - Edit profile: select blood group and department, save, and confirm updates persist to Supabase.
   - Re-open edit profile: confirm the custom dropdown pre-selects the user's existing department and blood group.
3. **Theme & Contrast Verification**:
   - Test in dark theme: verify dark background and bright white font with smooth hover highlights.
   - Test in light theme: verify clean white background and dark slate font.
