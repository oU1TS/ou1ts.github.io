# Implementation Plan - Mobile Navigation, Mandatory Profile Setup & Theme Contrast

Ensure mobile sidebar navigation reflects user auth state cleanly, guide users to complete mandatory profile details upon login, provide high-contrast styling for dropdown options in dark and light modes, and add the unified database heading to the Profile page.

## Proposed Changes

- **Target File**: [`index.html`](file:///d:/GitHub/[oU1TS]/ou1ts.github.io/index.html)

  - Retain `.sidebar-join` containing `<a href="#auth" class="sidebar-join-btn cta-btn" id="sidebarJoinBtn">...Join oU1TS</a>`.
- **Target File**: [`index.js`](file:///d:/GitHub/[oU1TS]/ou1ts.github.io/index.js)

    - When `isLoggedIn === false`: update `#sidebarJoinBtn` to display `<i class="fa-solid fa-handshake" style="margin-right: 8px;"></i>Join oU1TS` and link to `#auth`.
    - Ensure clicking `#sidebarJoinBtn` triggers `switchTab(targetId)` and closes the mobile sidebar cleanly.

### 3. Dropdown Menu Option Contrast Styling (Dark & Light Themes)
- **Target File**: [`index.css`](file:///d:/GitHub/[oU1TS]/ou1ts.github.io/index.css)
  - Declare `color-scheme: dark` in `:root` and `color-scheme: light` in `body.light-mode` so browser native popups, pickers, and menus inherit proper theme palettes.
  - Set `color-scheme: dark` on `.input-wrapper select`, and `color-scheme: light` on `body.light-mode .input-wrapper select`.
  - Explicitly style `.input-wrapper select option`:
    - **Dark Theme (Default)**: `background-color: #161b26; color: #f8fafc;`
    - **Light Theme (`body.light-mode`)**: `background-color: #ffffff; color: #0f172a;`
    - Disabled placeholder options (`Select Department`, `Select Blood Group`): `color: var(--text-muted);`
  - Guarantees high contrast (> 12:1 ratio) preventing white-on-white or low-contrast text in dark mode popups.

### 4. Mandatory Profile Information Completion Flow
- **Target File**: [`index.js`](file:///d:/GitHub/[oU1TS]/ou1ts.github.io/index.js) & [`index.html`](file:///d:/GitHub/[oU1TS]/ou1ts.github.io/index.html)
  - Define profile completeness criteria:
    - **Student ID**: numeric, non-empty, and not equal to `'OAUTH_USER'`.
    - **Department**: selected and valid.
    - **Batch**: non-empty.
    - **Blood Group**: selected from valid groups (`A+`, `A-`, `B+`, `B-`, `AB+`, `AB-`, `O+`, `O-`).
    - **Social Media**: at least ONE social link/handle (Facebook, Instagram, Telegram, or Discord) must be provided.
  - **Post-Login Profile Check**:
    - When a logged-in user visits `#profile` (or right after login/registration):
      - If required fields are incomplete, automatically show the edit form (`#profileEditForm`) and display an informational alert: `"Please complete your profile details (Student ID, Department, Batch, Blood Group, and at least one social link) to access all community features."`
      - While profile is incomplete, hide or disable the "Cancel" button on the edit form so users cannot dismiss the mandatory setup.
  - **Form Validation Enforcement**:
    - In `profileEditForm` submit listener and `updateProfile()` function:
      - Validate `student_id` (digits only).
      - Validate `department` (selected).
      - Validate `batch` (non-empty).
      - Validate `blood_group` (selected).
      - Validate that at least one of `social_facebook`, `social_instagram`, `social_telegram`, or `social_discord` contains input.
      - Display user-friendly alert if any requirement is unfulfilled.
